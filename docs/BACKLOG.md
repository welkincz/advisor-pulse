### #10 — Runner skeleton: stage DAG, run_id, retries, run_log

Milestone: M5 · Orchestration, checks & AI narrative · Labels: area:orchestration, status:blocked, size:M, agent:claude, wave:0

## Context
`pulse run --week YYYY-Www` executes registered stages in DAG order: restore_state, generate, ingest, dbt_build, checks, narrate, export, publish_sheets, persist_state. Stages are plain functions that return a StageResult(rows_in, rows_out, rows_quarantined, status, message). The runner adds tenacity retries (3 attempts, exponential backoff with jitter, only for retryable exceptions), writes one run_log row per attempt, stops downstream stages on FAIL, and exports the DAG as pipeline_graph nodes and edges. Stages that do not exist yet are no-ops returning SKIPPED.

## Owns (only touch these paths)
- `src/pulse/runner/`

- [ ] A run with all stub stages writes a complete run_log with SUCCESS/SKIPPED rows

- [ ] A FAILED stage marks downstream stages SKIPPED and the process exits non-zero
- [ ] `pulse run --dry-run` prints the plan without executing
- [ ] run_log.json export validates against its contract
